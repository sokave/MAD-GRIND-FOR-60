## Мета роботи

## Опис проєкту

У межах лабораторної роботи я підготував мобільний застосунок, присвячений університетським новинам. Застосунок складається з трьох екранів: головної сторінки, фотогалереї та профілю студента. Для переходу між ними використав нижню панель навігації Expo Router на основі React Navigation Bottom Tabs.

На **головній сторінці** відображаються картки із зображенням, заголовком, датою та коротким описом новини. Я додав пошук за текстом і категорією, очищення пошукового запиту та повідомлення, якщо результатів немає. Натискання на картку відкриває повний текст у модальному вікні.

У **фотогалереї** реалізував два способи відображення зображень: сітку у дві колонки та список. Натискання на зображення відкриває його для збільшеного перегляду.

На екрані **профілю** розмістив поля для ПІБ, електронної пошти та групи, перемикач сповіщень і кнопки збереження та скасування змін. Додав перевірку обов’язкових полів і формату email. Для локального збереження даних використав AsyncStorage. Збережений профіль відновлюється після повторного відкриття застосунку, а його дані використовуються у спільній шапці екранів.

Тексти новин є навчальними прикладами. Зображення зберігаються в проєкті локально. Перемикач сповіщень демонструє роботу з налаштуваннями: надсилання справжніх push-сповіщень у цій роботі не реалізоване.

## Інструкція із запуску

### Підготовка середовища

Для роботи з проєктом потрібні Node.js 24 LTS із npm та WebStorm. Для запуску на фізичному пристрої потрібен Expo Go, а для Android-емулятора — Android Studio зі встановленими Android SDK, Platform-Tools та Android Emulator.

Після встановлення Node.js потрібно перезапустити WebStorm і перевірити його доступність у терміналі:

```powershell
node -v
npm.cmd -v
```

У WebStorm необхідно відкрити папку `lab1`, у якій знаходиться `package.json`. Усі подальші команди виконуються з цієї папки.

Перед першим запуском потрібно встановити залежності:

```powershell
npm.cmd ci
```

У прикладах я використовую `npm.cmd`, щоб запускати npm у PowerShell без залежності від політики виконання PowerShell-скриптів.

### Запуск на фізичному пристрої через Expo Go

1. Підключити телефон і комп’ютер до однієї Wi-Fi мережі.
2. У терміналі WebStorm виконати:

   ```powershell
   npm.cmd start
   ```

3. Дочекатися запуску Metro та появи QR-коду.
4. На Android відкрити Expo Go і відсканувати QR-код. На iPhone відсканувати його камерою та відкрити проєкт у Expo Go; якщо буде запит входу, використати однаковий Expo-акаунт на телефоні та в Expo CLI.
5. Дочекатися завантаження застосунку. Термінал із Metro залишити відкритим.

Версія Expo Go має підтримувати SDK проєкту, зазначений у `package.json`. Якщо локальна мережа не дозволяє підключитися, можна зупинити сервер через `Ctrl+C` і запустити тунель:

```powershell
npm.cmd run tunnel
```

Після цього потрібно відсканувати новий QR-код. Для тунелю потрібен інтернет; Expo може запропонувати встановити додатковий пакет.

### Запуск в Android-емуляторі

1. В Android Studio відкрити Device Manager і створити віртуальний пристрій.
2. Вибрати модель телефона, завантажити відповідний образ Android і завершити налаштування.
3. Запустити пристрій кнопкою `▶` та дочекатися завантаження Android.
4. У терміналі WebStorm виконати:

   ```powershell
   npm.cmd run android
   ```

Якщо Metro вже запущено командою `npm.cmd start`, достатньо натиснути клавішу `a` в його терміналі.

Якщо Expo не знаходить Android SDK, потрібно перевірити його шлях у SDK Manager, встановити змінну `ANDROID_HOME` та додати папки `platform-tools` і `emulator` до `Path`. Після зміни змінних середовища потрібно перезапустити WebStorm.

### Запуск у браузері

Для відкриття вебверсії потрібно виконати:

```powershell
npm.cmd run web
```

Після запуску слід відкрити адресу, виведену в терміналі. Браузерний режим дозволяє швидко переглядати інтерфейс, проте не замінює перевірку на мобільному пристрої.

### Додаткові команди

| Команда | Призначення |
| --- | --- |
| `npm.cmd run clear` | Запуск Expo з очищенням кешу Metro |
| `npm.cmd run typecheck` | Перевірка типів TypeScript |
| `npx.cmd expo install --check` | Перевірка сумісності залежностей з Expo SDK |

## Основні способи запуску та особливості тестування

| Спосіб | Призначення | Особливості та відмінності під час тестування |
| --- | --- | --- |
| **Expo Go на телефоні** | Швидкий запуск проєкту на реальному Android або iOS пристрої | Дозволяє оцінити сенсорне керування, роботу клавіатури, читабельність і швидкодію на конкретному телефоні. Потрібна сумісність Expo Go з SDK. Доступні лише нативні модулі, які підтримує Expo Go. |
| **Android-емулятор** | Перевірка застосунку на віртуальному Android-пристрої | Можна використовувати різні розміри екранів та версії Android. Емулятор споживає ресурси комп’ютера, а його продуктивність і робота з обладнанням не повністю відповідають реальному телефону. |
| **Вебверсія** | Швидка перевірка інтерфейсу та основної логіки | Зручно перевіряти пошук, форму профілю й адаптацію до розміру вікна. Компоненти відображаються через React Native Web, тому вигляд, поведінка й доступні API можуть відрізнятися від Android та iOS. |
| **Development build** | Запуск власної нативної збірки для розробки | Підходить, коли потрібні нативні модулі або налаштування, яких немає в Expo Go. Потребує окремого складання та встановлення. Зміни нативних залежностей можуть вимагати повторної збірки. |
| **Expo Snack** | Онлайн-експерименти без локального встановлення середовища | Зручний для невеликих прикладів і навчання. Перенесення цього проєкту з Expo Router у Snack може потребувати адаптації структури та залежностей. |

LAN і tunnel визначають спосіб підключення пристрою до Metro. LAN працює через локальну мережу. Тунель дозволяє обійти обмеження локального підключення, але залежить від інтернету й може працювати повільніше.

Під час тестування важливо перевіряти не лише відображення екранів, а й пошук без результатів, відкриття та закриття модальних вікон, введення некоректного email, збереження і скасування змін. Для перевірки AsyncStorage потрібне повторне відкриття застосунку: одного Fast Refresh недостатньо, щоб оцінити відновлення даних після перезапуску.

## Висновки

У цій лабораторній роботі я ознайомився зі структурою Expo-проєкту та підготував застосунок із трьома екранами на React Native. Використав базові компоненти для відображення тексту, зображень, списків і форм. Для оформлення інтерфейсу застосував StyleSheet та Flexbox, а для переходів між екранами — нижні вкладки Expo Router.

Я розібрався з обробкою введення користувача, пошуком у локальному списку, перевіркою полів форми та збереженням профілю через AsyncStorage. Спільний стан дозволяє використовувати актуальні дані профілю на різних екранах.

Порівнявши способи запуску, я зробив висновок, що вебверсія зручна для швидкої перевірки інтерфейсу та логіки, емулятор — для перевірки різних конфігурацій Android, а фізичний пристрій — для оцінювання реальної взаємодії із застосунком. Ці способи доповнюють один одного. Успішна збірка або коректне відображення в браузері не гарантують однакової поведінки на телефоні, тому мобільний застосунок потрібно перевіряти й у цільовому середовищі.
