## Тема й мета

Кастомізація навігації в Expo Router, нативні модальні вікна та віртуалізація списків. Я використав ці можливості, щоб створити адміністративну панель університетського порталу новин.

## Що я реалізував

Я взяв за основу Expo-проєкт із лабораторної №2 та створив окремий застосунок «Кампус — Редакція» на Expo SDK 58.

| Розділ | Як працює |
| --- | --- |
| Вхід | Форма перевіряє дані демонстраційного адміністратора. Після успішного входу відкривається дашборд. За відсутності сеансу службові маршрути перенаправляють на `/login`. |
| Бічне меню | Власний компонент `AdminDrawerContent` містить чотири розділи, аватар з ініціалами, ім’я й пошту адміністратора та кнопку «Вийти». На телефоні меню відкривається з кнопки в заголовку. На широкому вікні воно закріплене збоку. |
| Дашборд | Показує загальну кількість новин, користувачів і логів, розподіл новин за статусом та останні дії. `useFocusEffect` перераховує показники, коли я повертаюся на екран. |
| Новини | У списку видно назву, категорію, статус, дату та зображення. Маршрут `/news/[id]` читає `id` через `useLocalSearchParams` і показує повний текст. Фільтри працюють за категорією та статусом. |
| Редактор | Створення й редагування використовують одну форму в модальному маршруті. Форма приймає заголовок, категорію, статус, HTTPS-адресу зображення й текст. Після збереження вона закривається. Видалення запитує підтвердження через `Alert.alert()` на Android та iOS і стандартний діалог браузера у вебверсії. |
| Користувачі | Видно ім’я, пошту, роль і статус кожного облікового запису. Кнопка із замком перемикає статус між «Активний» і «Заблокований». Фільтри працюють за роллю та статусом. |
| Системні логи | У журналі зберігаються час, автор і відомості про дію. Новий запис з’являється при вході, виході, створенні, редагуванні або видаленні новини та зміні статусу користувача. |

Для кожного з трьох локальних масивів я підготував по 60 демонстраційних записів. Новини, користувачі та логи зберігаються в спільному стані й записуються в AsyncStorage. Після перезапуску дані відновлюються, а вхід потрібно виконати знову. Перевірка навчального облікового запису виконується в застосунку.

У трьох списках використав `VirtualizedList`. Спільний компонент `RecordList` передає `getItem`, `getItemCount`, `keyExtractor` та `getItemLayout`. Висота рядка фіксована для кожного типу запису, тож зміщення обчислюється за формулою `(висота рядка + 9) * index`. Список починає з восьми рядків і рендерить наступні порціями. Відступи від системних панелей налаштовані через `react-native-safe-area-context`.

## Як запустити у WebStorm

1. Розпакуй архів і поклади папку `lab3` в корінь репозиторію. Відкрий у WebStorm саме `lab3`, де є `package.json`.
2. Переконайся, що встановлено Node.js 24 LTS версії 24.3 або новішої в цій гілці.
3. У Windows PowerShell виконай команди нижче й відкрий адресу, яку покаже Expo.

   ```powershell
   npm.cmd ci
   npm.cmd run web
   ```

4. Увійди з поштою `admin@example.com` і паролем `lab3demo`.

| Команда | Для чого |
| --- | --- |
| `npm.cmd start` | Запустити Metro. Для телефона відскануй QR-код у сумісній із SDK 58 версії Expo Go |
| `npm.cmd run android` | Відкрити застосунок в Android-емуляторі, який уже запущено через Device Manager |
| `npm.cmd run clear` | Перезапустити Metro з очищенням кешу |
| `npm.cmd run tunnel` | Запустити Expo через тунель, якщо телефон не підключається локально |
| `npm.cmd run typecheck` | Виконати перевірку TypeScript |

У Git Bash ті самі команди можна виконувати через `npm`. Перед переходом від вебверсії до запуску через Expo Go зупини поточний сервер клавішами **Ctrl+C**.

## Сценарій демонстрації

1. Увійди й перевір кількість записів на дашборді.
2. Створи новину, відкрий її зі списку та зміни заголовок або статус. Потім підтвердь видалення створеного матеріалу.
3. Застосуй фільтри новин за категорією і статусом. У розділі користувачів зміни статус облікового запису й перевір, як змінюється результат фільтрації.
4. Відкрий системні логи й звір послідовність дій. Повернися на дашборд, щоб побачити оновлені лічильники.

Для здачі завантаж папку `lab3` з цим README та скріншотами до репозиторію `MobileLabsRN2026`.

## Контрольні запитання

1. **Як кастомізувати бічне меню й заголовок стека?** Через `drawerContent` передав власний компонент, який отримує стан і методи Drawer. Він визначає активний розділ, відкриває потрібний маршрут і показує профіль адміністратора з кнопкою виходу. Через `screenOptions.header` у Stack новин передав власний заголовок. Із параметрів екрана він бере назву, а на деталях показує кнопку повернення.
2. **Чим `modal` відрізняється від `formSheet`?** `modal` відкриває екран поверх попереднього й підходить для форми з кількома полями. `formSheet` показує панель, яку можна перетягувати між заданими висотами. Для фільтрів я встановив `sheetAllowedDetents: [0.6, 0.9, 1]`. У вебверсії ті самі маршрути використовують прозоре модальне накладання.
3. **Для чого потрібен `useFocusEffect` і чим він відрізняється від `useEffect`?** `useFocusEffect` викликає передану функцію, коли екран отримує фокус, навіть якщо він залишався змонтованим. Передаю функцію через `useCallback`, щоб залежності були явними. `useEffect` запускається після монтування й зміни залежностей. Саме повернення на вже змонтований екран не змушує `useEffect` повторитися.

## Висновки й перевірка

Я навчився налаштовувати Drawer і заголовки Stack, відкривати редактор і фільтри як окремі маршрути та показувати великі масиви через `VirtualizedList`. Спільний стан дозволив оновлювати дані й додавати пов’язаний запис аудиту в межах однієї дії.

У браузері перевірив захищені адреси, вхід і вихід, створення, редагування й підтвердження видалення, обидві панелі фільтрів, зміну статусу користувача та оновлення дашборда. Також перевірив збереження даних після перезавантаження та послідовність усіх шести подій у журналі. Перевірка типів і експорт Expo для Web, Android та iOS пройшли. Поведінку нативних модальних вікон і системного діалогу видалення слід перевірити в Expo Go або на Android-емуляторі під час демонстрації.
